# EdgeSlicer 2.4.4.1

<!-- update-notice -->
2.4.4.1 stops the setup wizard from opening at every launch and fixes a FlashForge crash and macOS display problems.
Fixes:
- The setup wizard no longer opens each time EdgeSlicer starts (installs set up since 2.4.0.0, Windows and macOS).
- Clicking a FlashForge printer (Creator 5) in the Device tab no longer crashes EdgeSlicer.
- macOS: objects are no longer invisible or see-through in Prepare (since 2.3.8.5), and the app bundle has the EdgeSlicer icon.
- Linux: the Flatpak build compiles again.
<!-- /update-notice -->

Everything in [2.4.4.0](https://github.com/aceRage/EdgeSlicer/releases/tag/v2.4.4.0-edge) is included.

## Fixes

- **Setup wizard at every launch.** On any install first set up on 2.4.0.0 or later, the setup wizard opened again each time EdgeSlicer started, on Windows and macOS. The startup check still treated an empty "Customer Experience Improvement Program" setting as "setup never finished", but 2.4.0.0 removed that wizard page and preference, so nothing writes the setting any more. The wizard now opens by itself only when there is no configuration yet, when only the built-in default printer is installed, or when an older configuration never finished the wizard. The decision is written to the log (`config_wizard_startup: ... -> wizard: none`).
- **FlashForge Device tab crash** (Creator 5). Clicking a FlashForge printer added by IP address, serial number and check code crashed EdgeSlicer at once. Until the printer reported its model, the device page used model id 0, built no temperature rows and then read a row that was never created. The page now takes the model from the printer's own report (the saved id only stands in before that), the temperature panel skips rows it does not have and is rebuilt when the model becomes known, and a printer model this build does not know gets read-only temperature rows instead of a crash. A Creator 5 / 5 Pro added this way also gets its four-nozzle temperature and material panels and appears in the send dialog's device list again.
- **macOS: invisible or see-through objects** (since 2.3.8.5). Objects and the prime tower in Prepare could be invisible or look ghosted on macOS, whatever the view mode. Two texture inputs of the object shader, added with the drawn cut, shared one texture unit, which macOS refuses to draw. They now have units of their own. Windows and Linux are unchanged. The GL context EdgeSlicer gets (version, profile, renderer, depth bits, shader set) is now written to the log at startup, and a shader with this kind of conflict is reported as an error.
- **macOS app icon.** The app bundle (Finder, Launchpad, Applications) showed the old Snapmaker Orca "BETA" icon. It now has the EdgeSlicer icon, sized to Apple's icon grid so it matches the size of other app icons.
- **Linux build.** The Flatpak build of 2.4.4.0 failed on a missing include in the dual-nozzle reach check. No change in behaviour.
