Local patch (vs upstream commit 71dc66e)
----------------------------------------
prusa_fdm_mixer.cpp is NOT byte-identical to upstream. Two defensive changes in
hex parsing / input handling make the model usable in the slicer (upstream
throws std::invalid_argument; the slicer's legacy parse_hex_color is lenient):

  1. hex_to_rgb(): PARSE THE LEADING 6 HEX DIGITS after '#', IGNORING any
     trailing characters (was: throw unless input is exactly 6 hex digits).
     Return RGB{0,0,0} only when fewer than 6 leading hex digits are present.
     CRITICAL: the slicer stores colours as 8-digit "#RRGGBBAA" with alpha in
     many places (AMS / extruder / machine colours, e.g. #FFFFFFFF, #F0F0F0FF).
     The legacy parser reads substr(1,2)/(3,2)/(5,2) and ignores the alpha, so
     it colours them correctly; upstream's strict 6-digit check turned every
     alpha colour into black (and threw, crashing the dialog) under the demo.
     Matching the legacy leniency fixes both. Search "PATCHED (demo)" in the file.
  2. predict_lab(): return LAB{0,0,0} on an empty parts list (was: throw).

Verified: #F2754EFF->242,117,78 ; #FFFFFFFF->255,255,255 ; #F2754E->242,117,78 ;
#FFF/""/red -> 0,0,0 (same as legacy); mix(#F2754EFF,#0A6FFFFF @0.5)->106,105,146.
